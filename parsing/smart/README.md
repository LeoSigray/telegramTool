# Умный парсинг людей

Берёт Telegram-канал клиента и находит в чатах людей, которые **сами пишут о потребности** по его теме. На выходе Excel, где люди уже отсортированы по оценке PQI, у каждого есть объяснение «почему в списке», а отдельный лист хранит лог запуска.

Денег модуль не тратит: основную работу делают правила, словари и TF-IDF на чистом Python. Бесплатный облачный LLM (`api/llm.py`, по умолчанию OpenRouter free) проверяет только верхушку списка, а без LLM модуль тоже работает.

## Запуск

Из меню: `python main.py` → «4. Парсинг чатов» → «6. Умный парсинг людей».

Из командной строки (из корня проекта):

```bash
python -m parsing.smart --channel @client_channel
python -m parsing.smart --channel @client_channel --brief "интеграция Битрикс24 с 1С для магазинов" --days 14 --people 100
python -m parsing.smart --channel @client_channel --offline        # пересчёт по собранному, без Telegram
python -m parsing.smart --channel @client_channel --no-llm         # только правила
```

Результат: `data/smart_leads/<канал>_<дата>.xlsx` и `.log` рядом.

Перед первым запуском: `pip install -r requirements.txt` (добавлен `pymorphy3` для лемм). Нужен хотя бы один авторизованный аккаунт в `sessions/`; читает первый, другой можно выбрать через `--session`. Не запускайте парсинг той же сессией, которую в этот момент держит API-сервер (`api/server.py`).

## Как задаётся объём

Вместо числа источников вы указываете **сколько людей нужно** (`--people 100`). Парсер находит очередь подходящих чатов и читает их волнами по 5 (`--wave`). После каждой волны он пересчитывает людей по правилам и останавливается, когда набрал нужное число с запасом (×1,5: часть отпадёт после LLM и проверки аудитории клиента). Остальные чаты из очереди не читаются и в «Источниках» помечены «не понадобился». Если после LLM и проверки аудитории клиента людей стало меньше нужного, парсер дочитывает следующую волну (до 5 раз). Если чаты закончились, а людей не хватает, в логе будет предупреждение и подсказка: расширить окно `--days`, уточнить бриф или пересобрать профиль. Предел чтения за запуск: `--source-cap` (60).

## Как это работает

```
канал клиента → профиль → поиск источников → предфильтр → сбор сообщений
→ правила → тема → LLM (только топ) → авторы → PQI → Excel
```

1. **Профиль** (`profile.py`). Описание и посты канала дают частые термины и, через один вызов LLM, оффер, аудиторию, фразы покупателя, поисковые запросы и анти-портрет. Сохраняется в `data/smart_profiles/<канал>.json`. **Его можно править руками**: следующий запуск возьмёт правку. Пересобрать можно флагом `--rebuild-profile`.
2. **Источники** (`discovery.py`, `probe.py`). Поиск одинаковый для любого клиента и управляется параметрами (`--lang`, `--geo`, `--people`, пороги в `settings.py`).

   **Раунды поиска.** Нейросеть заранее генерирует пул из 50 запросов «где общаются покупатели» (`--queries`). Они идут порциями по 10 (`--per-round`): раунд поиска → отбор → чтение. Если людей меньше нужного, начинается следующий раунд с новой порцией. Когда пул кончился, нейросеть генерирует ещё 50 новых, зная уже использованные запросы и названия удачных чатов (до 3 догенераций). Без LLM запросы берутся из шаблонов вокруг терминов клиента. Остановка: людей набрано, либо два раунда подряд не дали новых подходящих чатов, либо достигнут `--max-rounds` (12). Каждый кандидат считается один раз, поэтому повторные запросы не тратят проверки.

   **Зёрна и граф.** Зерно — хороший чат: прошёл пробу с плотностью запросов по теме от 1 в неделю (`seed_min_y`) или уже дал людей. Зёрна **сохраняются для клиента между запусками**, поэтому разные формулировки запросов от нейросети не мешают: следующий запуск начинает с проверенных чатов (и перечитывает их, там новые запросы).
   - Пока зёрен меньше `--min-seeds` (5), раунды идут поиском по запросам.
   - Когда зёрен достаточно (или поиск перестал давать новое), раунды идут **по графу от зёрен**: пересылки (вес 1,0), похожие каналы (0,7), ссылки и @упоминания (0,5). Чат, на который ссылаются несколько зёрен, получает больший вес и проверяется первым.
   - Хорошие чаты, найденные графом, сами становятся зёрнами следующей ступени. Глубина `--graph-depth` (2).

   **Слова товара.** Профиль хранит `product_keywords`: как покупатель называет САМ товар (айфон, iphone, макбук…). Проба чата считает запросом только сообщения, где речь о товаре (или комментарий под постом о товаре). Чат, где за последние ~100 сообщений товар не упоминается ни разу, отбрасывается сразу, без чтения: так отпадают чаты про логистику и комиссии маркетплейсов.

   **Поиск по сообщениям** ищет чаты по сообщениям любого возраста: чат, где когда-то писали «куплю айфон», становится кандидатом, а живой ли он сейчас, решает проба.

   **Каталог** содержит только чаты, которые уже давали людей выше порога, поэтому не воспроизводит ошибки прошлых запусков.

   **Лимит времени** `--max-minutes` (45): по истечении парсер заканчивает шаг и собирает отчёт по найденному.

   **Откуда кандидаты:**
   - **каталог** — чаты, уже пробованные для прошлых клиентов и близкие по теме. Система умнеет с каждым запуском;
   - **поиск Telegram по названиям** — запросы «где общаются покупатели» (`community_queries` профиля: роль покупателя, его бизнес, площадки), плюс варианты «… чат» и с городами из `--geo`;
   - **похожие каналы** к каналу клиента;
   - **граф** — от лучших найденных чатов: каналы, из которых туда пересылают, ссылки `t.me/…` и `@…` в сообщениях, похожие каналы. Выключается `--no-graph`;
   - фразы покупателя в личных чатах аккаунта — **выключено по умолчанию**, `--search-my-chats`.

   **Отбор:**
   - мусор по названию и ранее признанные мусорными;
   - детальная проверка: публичный ли, есть ли комментарии у канала, размер (группы от 100, каналы от 300);
   - **проба** (последние ~100 сообщений): язык (доля на `--lang` не ниже 50%), активность (не меньше 0,3 сообщения в день, последнее не старше окна), мусор, **плотность запросов по теме клиента в неделю**;
   - чаты без сообщений по теме клиента отсеиваются.

   Очередь чтения сортируется по плотности запросов из пробы, а не по названию. Канал клиента и его обсуждение источниками не бывают. Читаются только публичные чаты, личные диалоги и профиль аккаунта не трогаются.

   **Развитие (не реализовано, нужен выбор сервиса):** веб-поиск `site:t.me` через свой SearXNG (бесплатно) или Brave Search API; платные каталоги TGStat или Telemetr с фильтрами по языку, стране, категории и размеру.
3. **Мусорные чаты** (`junk.py`, словарь `lexicon/junk_chat.txt`). Выбрасываются в два этапа:
   - **до чтения**, по названию и описанию: заработки, «без вложений», 18+, ставки и казино, накрутки и взаимопиар, обнал и пробив;
   - **после чтения**, по сообщениям окна. Чат выбрасывается целиком, если сработал хоть один порог: боты, анонимы и пересылки ≥ 50%, ссылки и контакты ≥ 50%, копипаст ≥ 30%, мусорная тематика ≥ 15%, реклама исполнителей ≥ 50%. При меньше 20 сообщениях по содержимому не судим.

   Мусорный чат запоминается и 30 дней не читается. Признаки видны на листе «Источники» в столбце «Признаки мусора». Пороги в `settings.py` (`junk_*`). Отдельные сообщения с мусорной тематикой тоже никогда не считаются запросом.
4. **Сбор** (`harvest.py`): сообщения групп и комментарии к постам каналов за окно `--days`. Сбор инкрементальный: повторный запуск дочитывает только новое (кеш `data/smart_parser.db`).
5. **Правила** (`features.py`, словари в `lexicon/`):
   - маркеры запроса («ищу», «посоветуйте», «сколько стоит»), слабые маркеры с весом вдвое меньше;
   - маркеры продавца;
   - приглашение в ЛС: вместе с запросом это плюс, без запроса — реклама;
   - ссылки, телефоны, эмодзи;
   - один и тот же рекламный текст в нескольких чатах;
   - ответы конкурентов в ветке;
   - «спасибо, уже нашли»;
   - «в лс не писать».
6. **Тема** (`relevance.py`): `R = 0.7 · покрытие терминов клиента + 0.3 · косинус TF-IDF`. Длинный подробный запрос не теряет в оценке. Вопрос в комментарии («сколько стоит?») получает тему от поста, под которым он написан. Флаг `--embeddings` добавляет локальные эмбеддинги (`pip install sentence-transformers`, бесплатно, но тяжело).
7. **LLM** (`llm_judge.py`): проверяется только топ по правилам, пачками по 20 сообщений, с кешем по тексту. Потолок задаёт `--llm-budget` (по умолчанию 25 вызовов). Если LLM два раза подряд ошибается или упирается в лимит, он отключается до конца запуска, и работа продолжается на правилах.
8. **Авторы** (`enrich.py`): био для верхушки (признак ЛПР), с паузами и кешем на 7 дней.
9. **Исключения**:
   - те, кому уже писали, и стоп-лист из базы рассылок (`data/database.db`);
   - **аудитория клиента** (`audience.py`): участники группы обсуждения его канала, подписчики (если читающий аккаунт админ) и авторы последних комментариев. Список кешируется на сутки. Лучшие 150 кандидатов дополнительно проверяются точечно (`GetParticipant`), потому что большие группы отдают не всех участников. Причина в «Отсеянных»: «уже в аудитории клиента».

## Интерес человека: текст + пересечения

Итоговая сортировка людей — по **интересу** (0–100), который складывается из двух частей:

- **Текст (горячесть).** Свежий явный запрос («ищу поставщика…», «скиньте прайс») — потребность прямо сейчас. Это главный сигнал, его вес 0,65 (`w_hot`).
- **Пересечения (близость к нише).** В скольких чатах ниши человек есть: где **пишет** (вес 1) и где **только состоит** (вес 0,6, по спискам участников), плюс сколько у него сообщений по теме. Вес 0,35 (`w_aff`). Чаты ниши взвешены: зёрна 1,0, остальные по плотности запросов, пробе и доле людей, которые есть и в других чатах ниши.

Почему текст важнее: больше всего чатов ниши у **продавцов и конкурентов**, они вступают во все такие чаты. Поэтому пересечения усиливают людей с запросом, а продавцы отсекаются: реклама в половине их сообщений и больше, вердикт LLM «продаёт сам», реклама в био.

**Порога по PQI нет**, порог стоит по итоговому «Интересу»: **`--min-interest 20`** по умолчанию (0–100, `0` — без порога). В отчёт берутся лучшие `--people` человек с интересом не ниже порога. При пороге 20 «тёплые» без запроса проходят редко: обычно только ЛПР с широким охватом ниши. Чтобы видеть всех тёплых, задайте `--min-interest 0`. Для решения «хватит ли читать чаты» парсер считает людей с PQI от 10 (`stop_pqi`), на отчёт этот внутренний порог не влияет.

Защита от «вытягивания» слабых:
- **Близость только усиливает запрос.** Вклад пересечений умножается на `G = min(1, горячесть / 0.5)`. Запрос с PQI 3 не поднять одним только числом чатов.
- **Вес чата зависит от того, обсуждают ли там товар клиента.** Множитель `min(1, 0.2 + 10 · доля сообщений о товаре)`. Чат селлеров WB, где товар клиента не упоминают, весит 0,2 от обычного. Доля видна в листе «Источники».
- **«Сообщения по теме»** считаются только там, где товар назван словом товара целиком.

Типы людей в Excel (тёплые включены по умолчанию, отключаются `--no-warm`; ранжируются по тому же «Интересу»):
- **горячий** — есть запрос; пересечения поднимают его выше других горячих;
- **тёплый** — запроса не писал, но пишет по теме в нескольких чатах ниши (или молча состоит минимум в 5, `silent_min_chats`). Ему лучше писать мягко, от темы чата.

Списки участников берутся **без вступления в чаты** (`--no-members` — выключить): Telegram отдаёт их для публичных групп, если админы не скрыли список. Скрытый список не увидит и вступивший, только админ, поэтому вступление ничего не даёт. Для канала берутся участники его группы обсуждения. В логе видно, у каких чатов список недоступен или скрыт. Списки хранятся только как пары «чат — id человека» и удаляются по сроку хранения вместе с сообщениями.

Лист **«Пересечения чатов»** показывает пары чатов с наибольшим числом общих людей: это одна аудитория.

## Поиск чатов через интернет (вместо поиска по названиям)

Чаты ищутся не поиском Telegram по названиям, а по статьям, подборкам и обсуждениям, где люди советуют чаты:

1. Нейросеть пишет ~20 запросов для поисковика: «лучшие телеграм чаты для …», «где общаются … в телеграм», «… site:vc.ru» и т.п. Описывается аудитория клиента, а не его товар.
2. Поисковик отдаёт статьи. Со страниц берутся ссылки `t.me/…` и `tgstat …/@…` (вес 1) и голые `@упоминания` (вес 0,4, это может быть автор). Боты и служебные адреса отбрасываются.
3. Очки чата — сумма по **разным сайтам** (один сайт — один голос). Самые советуемые (`web_resolves` = 25 за раунд) проверяются в Telegram и идут в обычную пробу. Статья — подсказка, а не гарантия.
4. Выдача и страницы кешируются на 7 дней. В листе «Источники» видно: «интернет (N сайт.): домены».

Поисковики идут цепочкой, каждый следующий — запасной:
- `GOOGLE_CSE_KEY` + `GOOGLE_CSE_CX` в `.env` — Google Programmable Search;
- `BRAVE_API_KEY` в `.env` — Brave Search API;
- библиотека `ddgs` (`pip install ddgs`) — бесплатно, без ключа, сама перебирает несколько поисковиков. **Рекомендуется**;
- DuckDuckGo HTML и Lite — без ключа, но после серии запросов временно блокируют IP (ответ 202).

Если недоступны все поисковики, раунд ищет по названиям в Telegram, как раньше, и пишет об этом в лог. Вернуть старый поиск принудительно: `--title-search`. Поиск по фразам покупателя в сообщениях и граф от зёрен остались без изменений.

## Ключевые слова: только те, что живут в Telegram

Слова товара и фразы покупателя задают и поиск чатов, и проверку «о товаре ли чат», и точечное чтение. Поэтому выдуманные нейросетью слова («нейрокурсы», «AI-онбординг») портили всё сразу. Теперь работают четыре защиты:

1. **Язык аудитории.** Перед генерацией берутся частые слова из комментариев под каналом клиента. Нейросеть получает их как образец того, как пишут настоящие покупатели.
2. **Строгий промпт.** Запрещены неологизмы, склейки через дефис и смешение языков. Фразы покупателя — по 2–3 слова, с примерами хороших и плохих.
3. **Проверка поиском Telegram** (один раз на профиль, ~1–2 мин; `--no-validate` — выключить). Каждое слово товара и фраза ищется по сообщениям публичных чатов, где аккаунт не состоит, за последние 90 дней. Слова без совпадений выбрасываются, остальные сортируются по частоте. Результат хранится в профиле (`keyword_hits`) и показан в логе.
4. **Совпадение целым словом/фразой** в леммах. Общие слова (`ai`, `курс`, `онлайн`, `бизнес`, …) и слова через дефис не считаются словами товара.

После обновления генератора старые слова и запросы профиля создаются заново автоматически.

## Точечное чтение (быстрее)

По умолчанию чат не читается целиком. Берутся последние 100 сообщений как контекст, остальное находит поиск Telegram **внутри чата** по 6 лучшим словам товара и 6 проверенным фразам покупателя (`targeted_terms`). Для канала берутся несколько свежих постов и посты, найденные по словам, а затем комментарии под ними. Если слов товара нет, чат читается целиком. Принудительно читать целиком: `--full-read`.

## Формулы

Источник:
`CQI = U · A · Rel / (1 + Comp) · (1 − Ad)`. Здесь U — авторы запросов в неделю, A — доля авторов с username, Rel — средняя тема, Comp — конкуренты в ветках, Ad — доля рекламы.

Человек:
`PQI = 100 · I · R · F · T · E · (0.5 + 0.5·A) · (0.7 + 0.3·CQĨ) · бонус`

| | Фактор | Откуда |
|---|---|---|
| I | намерение | правила; если LLM ответил «покупатель и запрос» — `max(правила, 0.6 + 0.4·конкретика)` |
| R | тема | покрытие терминов и TF-IDF; с LLM — среднее с его оценкой темы |
| F | свежесть | `exp(−часы / 72)` |
| T | ветка | `1 / (1 + конкуренты)`; 0, если автор закрыл запрос |
| E | активность | статус в сети и свежесть сообщения |
| A | ЛПР | 1, если в био «основатель», «директор», «CEO» и т.п.; 0.8 по оценке LLM; иначе 0.3 |
| бонус | | +10% за каждый дополнительный запрос автора (до +30%) |

Уровни: **A ≥ 25**, **B ≥ 10**, остальные C. Это стартовые пороги, их стоит уточнить по разметке.

## Остановка и дособорка отчёта

- **Ctrl+C один раз**: парсер заканчивает текущий шаг и сохраняет отчёт по тому, что уже собрано. **Ещё раз** — прервать сразу.
- Если запуск оборвался без отчёта: `python -m parsing.smart --channel @канал --session personal --finish` соберёт отчёт по уже прочитанным чатам, без нового поиска, но с проверками и био.

## Excel

| Лист | Что там |
|---|---|
| Запас | те, кто не дотянул до порога `--min-pqi` (10) или не поместился в нужное число; их можно взять, если людей не хватит |
| Люди | ровно столько людей, сколько просили (`--people`), по убыванию PQI. О человеке: био, когда был в сети, Premium, ЛПР по био, сколько сообщений написал за окно, в каких чатах пишет, другие его запросы. Дальше: username (ссылка), ссылка на сообщение, цитата, источник, факторы, «почему в списке», предупреждения, столбец «Разметка (да/нет)». У ячейки PQI есть примечание с разложением формулы |
| Без username | те же поля для людей, которым сейчас нельзя написать |
| Источники | все найденные чаты: взят или отброшен и почему, CQI и его составляющие |
| Отсеянные | до 40 примеров на каждую причину отсева: удобно ловить ошибки словарей |
| Профиль | профиль клиента и параметры запуска |
| Лог | воронка в цифрах и весь лог запуска |

## Настройка качества

1. Разметьте «да»/«нет» у 50–100 верхних строк на листе «Люди».
2. Запустите `python -m parsing.smart.evaluate data/smart_leads/<файл>.xlsx`: получите precision@k, точность по уровням и источникам и средние факторы у «да» и «нет».
3. Правьте словари в `lexicon/` (по фразе на строку; `~` в начале делает маркер слабым), веса `W` в `features.py`, пороги в `settings.py`.
4. Проверьте результат без запросов к Telegram: `--offline` пересчитывает по уже собранному.

## Лимиты и ограничения

- Бесплатные модели имеют небольшие лимиты по запросам в минуту и в день (точные цифры смотрите в кабинете провайдера). Один запуск тратит до `llm_budget + 1` вызовов. Кеш не тратит вызовы на уже проверенные сообщения.
- Telegram: один читающий аккаунт, паузы между запросами, FloodWait выдерживается (дольше `max_flood_wait` не ждём, этап пропускается).
- Данные: сообщения старше `retention_days` (30) удаляются из кеша при каждом запуске; авторы, просившие не писать в ЛС, исключаются.

Тесты: `python -m unittest tests.test_smart_parser` (без Telegram и LLM, на синтетике и фейковом клиенте).
