# Перенос на сервер (VPS)

Зачем: без VPN провайдер не пропускает SOCKS-запросы к Telegram даже через твой прокси
(см. `python check_proxy.py` — пункт «2в»). На сервере вне России этого нет: ни VPN,
ни ноутбук не нужны, прогрев идёт круглые сутки и не засыпает.

Что видит Telegram: только IP прокси (США). Сервер нужен лишь как «чистая дорога» до прокси.
Прокси на сервере остаётся обязательным (жёсткий режим) — без него программа не подключится.

> Инструкция составлена по коду проекта; на Linux-сервере я её не запускал. Первый запуск
> лучше пройти по шагам и сверять вывод.

---

## 0. Выбор сервера

- Любой VPS **вне РФ** (Нидерланды / Германия / Финляндия / США), **Ubuntu 24.04 LTS**,
  1 vCPU, 1–2 ГБ RAM, 10–20 ГБ диска. Для этой программы хватает самого дешёвого тарифа.
- Оплата зарубежным хостерам российскими картами часто не проходит — проверь заранее условия
  оплаты у выбранного хостера (есть и такие, что принимают рубли).
- IP сервера должен достучаться до прокси (проверяется в шаге 4). Если у прокси включена
  авторизация по IP — добавь IP сервера в белый список в панели Proxy-Seller.

## 1. Подготовка на ноутбуке (важно!)

**Нельзя, чтобы одна и та же сессия Telegram работала одновременно с двух машин.** Это сигнал
дублирования ключа — Telegram может сбросить сессию. Поэтому:

1. Останови прогрев/рассылку на ноутбуке (Ctrl+C) и **выйди из программы через пункт 0**
   (при штатном выходе свежие сессии записываются в базу).
2. Не запускай программу на ноутбуке, пока она работает на сервере (и наоборот).
3. По желанию убери мёртвые аккаунты из прогрева: Прогрев → 6 (Сбросить) → выбрать
   `255328191 255328271 258904526 261913374`. Живые не трогай.

Собери архив (PowerShell, из любой папки; `tar` встроен в Windows 10/11):

```powershell
tar --exclude=.venv --exclude=__pycache__ --exclude=.git --exclude=desktop -czf $HOME\telegramtool.tgz -C E:\Futter telegramTool
```

В архив попадут: код, `.env` (ключи), `data/database.db` (**сессии аккаунтов, прокси, состояние
прогрева**), `sessions/`, `accounts/`, `foricons/`, `data/targets.xlsx`, `data/warmup_channels.txt`.
Это секреты — не отправляй архив через мессенджеры и не клади в облако.

## 2. Первый вход на сервер

С ноутбука (PowerShell; OpenSSH есть в Windows):

```powershell
ssh root@IP_СЕРВЕРА
```

На сервере — создай пользователя, под которым всё будет работать, и закрой вход по паролю:

```bash
adduser --disabled-password --gecos "" tg
mkdir -p /home/tg/.ssh && cp ~/.ssh/authorized_keys /home/tg/.ssh/ 2>/dev/null; chown -R tg:tg /home/tg/.ssh
apt update && apt -y upgrade
apt -y install python3 python3-venv python3-dev build-essential tmux ufw
ufw allow OpenSSH && ufw --force enable
timedatectl set-timezone UTC
```

(Если хостер выдал вход только по паролю — сначала настрой вход по SSH-ключу, затем
отключи парольный вход в `/etc/ssh/sshd_config`: `PasswordAuthentication no`, `systemctl restart ssh`.)

`build-essential` и `python3-dev` нужны: пакет `tgcrypto` (ускоряет Telegram) собирается из исходников.

## 3. Загрузка проекта

С ноутбука:

```powershell
scp $HOME\telegramtool.tgz tg@IP_СЕРВЕРА:/home/tg/
```

На сервере (`su - tg` или новый `ssh tg@IP_СЕРВЕРА`):

```bash
cd ~ && tar -xzf telegramtool.tgz && rm telegramtool.tgz
cd telegramTool
chmod 600 .env
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

Установка может занять несколько минут (pandas, tgcrypto). Если `pip` ругается на конкретный
пакет — пришли мне текст ошибки.

## 4. Проверка прокси ДО запуска аккаунтов

```bash
cd ~/telegramTool
.venv/bin/python check_proxy.py
```

Ожидаемый результат на сервере: пункты **2, 2б, 2в, 4 — «доходит / принята / открыт / работает»**.
Пункт 3 (прямой Telegram) тоже должен работать — для программы он не нужен.

- Пункт 4 «НЕ работает» → прокси недоступен с сервера: проверь срок аренды, логин/пароль, белый
  список IP в панели прокси. Запускать прогрев не надо.

Проверь, что прокси записан в базе (шапка меню покажет `socks5://хост:порт` без пароля):

```bash
.venv/bin/python main.py        # → 2 (Telegram): строка «Прокси: [socks5://136.162.193.26:50101]»
                                #   выйти: 0, 0
```

## 5. Запуск прогрева (вручную, в tmux)

`tmux` — «окно, которое живёт на сервере»: закрыл ноутбук — программа продолжает работать.

```bash
tmux new -s tg
cd ~/telegramTool && .venv/bin/python main.py
```

Дальше как на ноутбуке: **2 (Telegram) → 7 (Прогрев) → 2 (Продолжить прогрев)**.
Отключиться, оставив работать: **Ctrl+B, затем D**. Вернуться: `tmux attach -t tg`.

Прогресс прогрева хранится в `data/database.db` на сервере — он продолжится с того места, где
остановился на ноутбуке.

## 6. Автозапуск после перезагрузки сервера (необязательно)

Без меню и вопросов: команда `python main.py warmup-resume` продолжает прогрев всех
активных аккаунтов. Когда прогрев завершён — выходит сама (код 0). При поломке прокси
завершается с ошибкой (код 2) — программа остановлена, как ты и просил.

Файл `/etc/systemd/system/telegramtool.service` (под root):

```ini
[Unit]
Description=Telegram warmup
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=900
StartLimitBurst=5

[Service]
User=tg
WorkingDirectory=/home/tg/telegramTool
ExecStart=/home/tg/telegramTool/.venv/bin/python main.py warmup-resume
Restart=on-failure
RestartSec=60
Environment=PYTHONUNBUFFERED=1
Environment=PYTHONIOENCODING=utf-8

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now telegramtool
journalctl -u telegramtool -f        # смотреть журнал (Ctrl+C — выйти из просмотра)
systemctl stop telegramtool          # остановить
```

`StartLimit*`: если прокси сломан, сервис попробует перезапуститься максимум 5 раз за 15 минут и
остановится — он не будет бесконечно долбиться в сеть.

**Не запускай одновременно** сервис и ручной `main.py` с прогревом — две копии на одних аккаунтах
дадут конфликт сессий. Для ручной работы сначала `systemctl stop telegramtool`.

## 7. Рассылка с сервера

Так же через tmux: **2 → 3 (Рассылка)**. Многострочный текст вставляется через ssh нормально
(завершение — строка `END`). Целевая таблица `data/targets.xlsx` — на сервере; новую загрузи:

```powershell
scp E:\Futter\telegramTool\data\targets.xlsx tg@IP_СЕРВЕРА:/home/tg/telegramTool/data/
```

## 8. Обновление кода и резервные копии

- Новый код — копируй **только файлы кода**, не затирай `data/database.db` и `sessions/`
  (на сервере они свежее ноутбучных):

  ```powershell
  scp E:\Futter\telegramTool\warmup\runner.py tg@IP_СЕРВЕРА:/home/tg/telegramTool/warmup/
  ```

- Копия базы раз в сутки (под пользователем `tg`, `crontab -e`):

  ```
  0 4 * * * cp /home/tg/telegramTool/data/database.db /home/tg/telegramTool/data/database.bak-$(date +\%a)
  ```

  Скачать на ноутбук: `scp tg@IP_СЕРВЕРА:/home/tg/telegramTool/data/database.db .`

- Вернуться на ноутбук: остановить сервис/tmux на сервере, скопировать оттуда `data/database.db`
  и `sessions/`, только потом запускать локально.

## 9. Безопасность

- Вход только по SSH-ключу, пароль отключён; файрвол `ufw` включён (шаг 2).
- `.env` и `database.db` читает только пользователь `tg` (`chmod 600`).
- FastAPI-сервер (`api/server.py`) — это мессенджер «Диалоги». Он слушает только `127.0.0.1:9000` и снаружи
  недоступен: на ноутбуке открывается через SSH-туннель (`messenger.bat`). Не открывай порт 9000 в `ufw`.
- Логин/пароль прокси хранятся в `database.db` открытым текстом, как и раньше; в журналах и на
  экране программа их не печатает.

## 10. Мессенджер «Диалоги» — служба, которая работает всегда

Мессенджер ловит ответы на рассылку. Он должен быть включён **постоянно**, поэтому он стоит как служба systemd
(`telegramtool-inbox`): стартует вместе с сервером, сам перезапускается после падения, не зависит от окон tmux
и от ноутбука.

- Установка/запуск — один раз двойным кликом по `messenger.bat` (кнопка сама ставит службу; повторный клик ничего
  не ломает). Дальше этот же ярлык просто открывает «Диалоги» в браузере.
- Проверка: ярлык «Мессенджер - статус» (`messenger.bat -Status`) показывает РАБОТАЕТ / НЕ РАБОТАЕТ, включён ли автозапуск,
  сколько аккаунтов слушает. На сервере: `systemctl status telegramtool-inbox`, журнал: `journalctl -u telegramtool-inbox -f`.
- Выключить насовсем: ярлык «Мессенджер - выключить» (`messenger.bat -Off`, просит ввести YES). Включить обратно — клик по «Мессенджер (Диалоги)».
- Аккаунты делятся автоматически: когда консольная рассылка или прогрев берут аккаунт, мессенджер его отдаёт
  (аренда `accounts/leases.py`, продлевается каждые 30 с), а когда те закончили — забирает обратно за ~5 секунд и
  **догоняет всё, что пришло за это время** (при каждом подключении и ещё раз в 30 минут, за последние 7 суток).
  Останавливать мессенджер перед рассылкой не нужно.
- Старые ответы (пришли до включения мессенджера или раньше, чем за 7 суток): в «Диалогах» кнопка
  **«⬇ Загрузить старые ответы»** — спросит, за сколько дней, и подтянет ответы людей из вашей рассылки со всех
  подключённых сейчас аккаунтов. Время у сообщений настоящее (из Telegram), повторная загрузка дублей не создаёт.
  Аккаунты, занятые в этот момент рассылкой/прогревом, пропускаются (кнопка покажет сколько) — нажмите ещё раз позже.
- `deploy.bat` после заливки кода сам перезапускает службу, чтобы она подхватила новый код.
