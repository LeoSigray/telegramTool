# Умный парсинг людей — что реализовано

Ветка: `smart-parser` (репозиторий LeoSigray/telegramTool). Код: `parsing/smart/`. Тесты: `tests/test_smart_parser.py` (45 тестов). Запуск: меню `main.py` → «Парсинг чатов» → 6, либо

```
python -m parsing.smart --channel @канал_клиента --people 50
```

## 1. Задача

Под одного клиента (его Telegram-канал) найти людей, которым нужен его продукт: свежие запросы покупателей и «тёплых» людей из его ниши. На выходе Excel со списком, отсортированным по итоговому «Интересу», с причинами, логом и данными о каждом человеке.

Жёсткие ограничения:
- **Нулевые затраты.** Нейросеть только бесплатная облачная (цепочка Groq-моделей через `api/llm.py`), остальное — правила, статистика, лемматизация. Без нейросети тоже работает (хуже).
- **Личный аккаунт не трогаем.** Берутся только рабочие аккаунты из базы, при отказе автоматически берётся другой.
- **В чаты не вступаем,** читаем только публичное.
- **Не пишем людям**, кого клиент уже имеет в своей группе/канале, кому уже писали, кто в стоп-листе или просил не писать.

## 2. Источники чатов (только три)

Ручных списков, постов клиента и своих диалогов нет. Чаты находятся тремя способами:

1. **Поиск через интернет** (раунды, `websearch.py`). Нейросеть пишет ~20 запросов для поисковика («лучшие телеграм чаты для …», «где общаются … в телеграм», «… site:vc.ru»), в раунде берётся 4. Со страниц статей и подборок берутся ссылки `t.me/…`; чат, который советуют несколько разных сайтов, весит больше. Самые советуемые (25 за раунд) проверяются в Telegram. Поисковики идут цепочкой: Google CSE / Brave (если есть ключ) → библиотека `ddgs` → DuckDuckGo. Если недоступны все, раунд ищет по названиям в Telegram, как раньше (`--title-search` — принудительно по-старому). Когда запросы кончились, нейросеть пишет новые (до 3 раз).
2. **Похожие каналы и граф от «зёрен».** Зёрна — чаты, которые реально дали людей с запросами (≥5 штук, хранятся между запусками). От них идёт обход графа: пересылки (вес 1.0), рекомендации Telegram (0.7), ссылки (0.5), глубина 2. Кандидаты ранжируются по повторяющимся связям с разными зёрнами.
3. **Поиск по сообщениям.** Фразы покупателя («посоветуйте нейросеть для…») ищутся глобальным поиском по сообщениям публичных чатов; чат, где аккаунт не состоит, становится кандидатом.

## 3. Фильтрация чатов

**Проба** (последние ~100 сообщений каждого кандидата, кешируется на сутки):
- язык (по умолчанию `ru`, доля ≥50%), активность (≥0.3 сообщ./день), живой ли чат;
- размер (группа ≥100, канал ≥300 участников);
- доля сообщений по теме клиента;
- упоминание **продукта клиента целым словом** (чат селлеров WB без товара клиента отсекается);
- мусор (`junk.py`): боты, заработки, 18+, раздачи, накрутки, массовая реклама, словарь `junk_chat.txt`;
- оценка запросов по теме в неделю.

**CQI** (качество чата) = `U · A · Rel / (1 + Comp) · (1 − Ad)`: авторы запросов в неделю, доля авторов с username, средняя тема, конкуренты в ветках, доля рекламы. В каталог попадают только продуктивные чаты.

## 4. Сбор сообщений

- Группы и каналы с комментариями (посты + комментарии под ними).
- **Точечное чтение (по умолчанию):** последние 100 сообщений + поиск Telegram внутри чата по 6 словам товара и 6 проверенным фразам. Для канала — свежие посты и найденные по словам, затем комментарии. Если слов нет — читается целиком. `--full-read` — читать всё.
- Инкрементально: позиция чтения хранится в SQLite (`data/smart_parser.db`), повторный запуск не перечитывает историю. Срок хранения 30 дней.
- Паузы, обработка FloodWait, один плохой источник не роняет запуск.

## 5. Ключевые слова, привязанные к реальности

Раньше нейросеть выдумывала слова («нейрокурсы», «AI-онбординг»), и это портило поиск, фильтры и ранжирование. Теперь:

1. **Язык аудитории:** частые слова из комментариев под каналом клиента даются нейросети как образец.
2. **Строгий промпт:** без неологизмов, склеек через дефис и смешения языков; фразы покупателя по 2–3 слова, с примерами.
3. **Проверка в Telegram** (один раз на профиль): каждое слово и фраза ищется в публичных чатах за 90 дней; без совпадений — выбрасывается; остальные сортируются по частоте; в лог попадает результат.
4. **Совпадение целым словом/фразой в леммах** (`PhraseMatcher`); общие слова (`ai`, `курс`, `онлайн`, `бизнес`…) и слова через дефис не считаются словами товара.

При смене версии генератора (`QUERIES_VERSION`) старые слова и запросы профиля пересоздаются сами.

## 6. Оценка запроса человека (PQI)

`PQI = 100 · I · R · F · T · E · (0.5 + 0.5·A) · (0.7 + 0.3·CQI) · бонус`

| | Фактор | Смысл |
|---|---|---|
| I | намерение | словарь маркеров запроса («ищу», «кто делает», «посоветуйте»), вопрос, конкретика (бюджет/сроки); при проверке нейросетью — `max(правила, 0.6 + 0.4·конкретика)` |
| R | тема | покрытие терминов клиента + TF-IDF (`0.7·coverage + 0.3·cos`); с нейросетью — среднее |
| F | свежесть | `exp(−часы/72)` |
| T | ветка | `1/(1+конкуренты)`; 0, если автор закрыл запрос |
| E | активность | статус «в сети» и свежесть |
| A | ЛПР | «основатель/директор/CEO» в био → 1, иначе 0.3 |
| бонус | | +10% за каждый дополнительный запрос (до +30%) |

Дополнительно отсекаются: продавцы и реклама («под ключ», «пишите в лс»), конкуренты, дубликаты (SimHash), закрытые запросы («уже нашёл»), просьбы не писать, боты и удалённые.

**Нейросеть** (бесплатная цепочка `gpt-oss-120b → qwen → gpt-oss-20b`): пачки по 20 сообщений, JSON-ответ, кеш в SQLite, разбор лимитов («жду 17 с»), отключение модели при суточном лимите, автоподбор доступных моделей (`llm_models`). Ограничение — 25 вызовов на запуск.

## 7. Итоговый «Интерес» (0–100) и пересечения чатов

Сортировка людей — по интересу, который складывается из текста и пересечений:

- **Горячесть** `hot = min(1, PQI / 40)`, вес 0.65.
- **Близость к нише** `aff = 1 − exp(−(охват/2.5 + сообщений_о_товаре/6))`, вес 0.35. Охват = сумма весов чатов, где человек **пишет**, + 0.6·сумма весов чатов, где **только состоит** (списки участников берутся без вступления; скрытые списки видны в логе).
- **Вес чата:** зёрна — 1; остальные `(0.3 + 0.7·max(CQI, проба, пересечение людей))·P`, где `P = min(1, 0.2 + 10·доля сообщений о товаре)` — чат селлеров без товара клиента весит 0.2.
- **Защита от слабых:** близость умножается на `G = min(1, hot/0.5)`. Запрос с PQI 3 одними чатами не вытянуть.
- **Горячий:** `100·(0.65·hot + 0.35·aff·(0.5+0.5·ЛПР)·G)`. **Тёплый** (запроса не писал, но в нескольких чатах ниши): `100·0.35·aff·E·(0.5+0.5·ЛПР)`.
- **Продавцы** отсекаются независимо от числа чатов: реклама в ≥50% сообщений, вердикт нейросети, реклама в био.
- **Уровни:** A ≥ 40, B ≥ 20, остальные C. Порог **`--min-interest`** (по умолчанию 20; 0 — без порога) режет и лист «Люди», и «Без username».

Что важнее — текст или число чатов: **текст** (явный свежий запрос). Пересечения усиливают запрос и дают отдельный «тёплый» список молчащих, но живущих в нише людей (им нужно ≥5 чатов, `silent_min_chats`).

## 8. Исключения

- **Уже в аудитории клиента:** список участников + комментаторы обсуждения канала + точечная проверка `GetParticipant` для лучших кандидатов.
- **Уже писали / стоп-лист:** проверка по базе рассылок проекта (`--no-contacted-check` отключает).
- **Био** (для ЛПР): `GetFullUser`, кеш 7 дней, ключ доступа к профилю восстанавливается перечитыванием сообщения.

## 9. Управление запуском

- **`--people N`** — сколько людей нужно; парсер читает чаты волнами по 5, считает подходящих (с запасом ×1.5), и ищет новые раунды, пока не наберёт или не кончатся попытки (3 пустых раунда подряд — стоп).
- **Мягкая остановка Ctrl+C:** заканчивает текущий шаг и сохраняет отчёт по уже собранному (повторный Ctrl+C — аварийный выход). Лимит времени `--max-minutes` (45).
- **`--finish`** — дособрать отчёт по прочитанному без поиска и чтения; **`--offline`** — пересчёт по базе без Telegram.
- **Аккаунты:** выбираются рабочие по очереди, при отказе (например `AuthKeyDuplicated`) берётся следующий; личный `personal` не используется, если не указан в `--session`. Вход через `login.py` (код вводит пользователь).

## 10. Excel-отчёт

Листы: **Люди** (интерес, уровень, тип, username, био, ЛПР, чаты где пишет/состоит, цитата и ссылка на сообщение, PQI и его факторы, «почему в списке», предупреждения, колонка для разметки), **Запас** (если задан `--reserve`), **Без username**, **Отсев** (причина каждого отброшенного), **Источники** (статус, причина, CQI, вес, доля сообщений о товаре), **Пересечения чатов**, **Лог**. Защита от формул-инъекций в ячейках.

## 12. Известные ограничения

- Качество зависит от точности слов товара и бесплатных лимитов нейросети; без неё работают только правила.
- Скрытые списки участников недоступны; люди без username попадают в отдельный лист (написать им нельзя).
- Сессии аккаунтов слетают (`AuthKeyDuplicated`), если один аккаунт используется с двух IP/процессов одновременно — нужен один процесс и один постоянный IP на аккаунт.
- При пороге `--min-interest 20` «тёплые» без запроса проходят редко; для них — `--min-interest 0`.
- Пороги уровней A/B стартовые; для калибровки есть `evaluate.py` и колонка разметки.
